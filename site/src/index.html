Descriptionhow it works

The VM pushes. Your Mac already has the tree.

Network drives feel slow because every listing waits for a round trip. {{name}} keeps the whole folder tree on your Mac and lets the VM tell it what changed.

The daemon watches

A small Rust daemon on the VM indexes the folder and watches it with inotify. On a network filesystem, or for folders beyond the VM's inotify watch limit, it falls back to polling every 1–30 s, and {{doctor_cmd}} tells you when.

One ssh connection

Every change is pushed over a single ssh connection, using your ~/.ssh/config, agent, ProxyJump and Tailscale. No ports are opened.

Listing never waits

Your Mac keeps a local replica of the whole folder tree. Opening a folder in Finder is a local lookup. Heavy folders such as node_modules and .git are listed the first time you open them.

Contents on demand

A file downloads the first time you open it. Small files are fetched ahead when you look at their folder. Saves go straight back.

Verificationwhat runs before a change lands

How it is checked, in the order it runs.

The hardest behaviour lives inside fileproviderd, a macOS daemon that CI cannot run. So there is a stand-in, and the engine gets hit from every side.

  1. fpsim

    A simulator of macOS's fileproviderd

    It drives the engine through the same IPC the Finder extension uses and models File Provider quirks measured on macOS: folders enumerated only once, backoff after errors, failed fetches never retried, case and Unicode twins. They come from the 81-entry catalog of the open sshdrive project, credited as prior art. Eviction, Finder decorations and extension launch timing are not modelled.

    29 of 81quirks modelled
  2. fuzz

    Randomised concurrent Mac and agent edits

    Atomic saves, renames, rm -rf and git checkout-style churn on the VM. Finder operations on the Mac. Killed daemons, cut links and crash replays. The trees must converge, and no write on the VM may be lost.

    500/500seeds pass
  3. stress

    Stress campaigns with timing perturbations

    A real directory churned with hard links and daemon restarts, under several timing shapes. The replica is checked against the disk in both directions.

    disk ⇄ replicachecked both ways
  4. bench

    A network-shaped benchmark against sshfs

    Both cross the same kernel-shaped link. The numbers above come from it, with their conditions.

    {{b.profile}}and other profiles
  5. review

    Adversarial review

    Reviewers attacked the design and the code. Every finding was reproduced independently before it was fixed.

    repro firstthen fix
  6. mac

    Not yet run on a real Mac

    The Mac app builds in CI. Measuring what you see in Finder on real hardware is the last step before release, and it has not happened yet.

    openbefore release
Securitywhat it touches

It rides the ssh you already trust.

no open ports
{{name}} opens no listening port on either machine. Everything goes through one session started by your system ssh.
no stored secrets
{{name}} never stores passwords, passphrases or keys. With key-based ssh nothing is asked. If your ssh needs a password, a 2FA code or trust in a new host key, the Mac app shows ssh's own prompt when you connect. Background reconnects never prompt.
VM = untrusted input
Symlinks cannot reach outside the shared folder. Executable bits are hidden by default.
conflict copies
If you and the agent change the same file, you get a conflict copy next to it. Nothing is overwritten silently.
sha256-verified
The daemon binary is checked against its SHA-256 before it runs on the VM.

A conflict copy is named like
invoices (conflict from your-mac 2026-10-01 14.05).py

The daemon keeps its own state outside the shared folder.

Questionsyou might have

Questions you might have.

Can I use it today?

Not yet. It is pre-release. The source is at github.com/{{repo_label}} ({{repo_state}}), the npm package is not published yet, and {{domain}} is coming soon.

Does it download my whole repo?

No. Names, sizes and dates sync up front; heavy folders such as node_modules and .git are listed when you first open them. A file's contents download when you open it. Small files are fetched ahead when you look at their folder.

Does it work with Tailscale or a bastion host?

If ssh dev-box works from your Mac, {{name}} can use it. It reads your ~/.ssh/config, agent and ProxyJump.

What if my agent and I edit the same file?

You get a conflict copy next to the file. Neither version is lost.

My folder is on NFS. Does it work?

Yes, with polling. inotify does not see changes that other machines make on a network filesystem, so the daemon polls there.
